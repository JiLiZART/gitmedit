<task type="auto" tdd="true">
  <name>Task 1: Implement TerminalGuard with Drop cleanup and panic hook</name>
  <files>src/terminal.rs, src/main.rs</files>
  <behavior>
    - `TerminalGuard::new()` calls `crossterm::terminal::enable_raw_mode()` and returns a guard
    - When `TerminalGuard` is dropped, `crossterm::terminal::disable_raw_mode()` is called; errors are suppressed with `let _ = ...`
    - `install_panic_hook()` installs a hook that calls `disable_raw_mode()` and then invokes the original panic handler
    - The hook does NOT call `LeaveAlternateScreen` — we never enter alternate screen (IO-06)
    - The hook suppresses errors from `disable_raw_mode()` to avoid masking the panic message
    - `TerminalGuard::terminal()` returns a `ratatui::Terminal` backed by `CrosstermBackend` pointing at stdout — configured WITHOUT `EnterAlternateScreen`
  </behavior>
  <action>
Create `src/terminal.rs`:

1. `pub fn install_panic_hook()`: Captures the original panic hook with `std::panic::take_hook()`, installs a new hook that:
   - Calls `let _ = crossterm::terminal::disable_raw_mode();`
   - Does NOT execute `LeaveAlternateScreen` (we never enter it — this is the IO-06 constraint)
   - Calls `original_hook(panic_info)` to preserve normal panic output

   This function must be called before ANY terminal state is changed.

2. `pub struct TerminalGuard` — a newtype holding `ratatui::Terminal<CrosstermBackend<std::io::Stdout>>`.

3. `impl TerminalGuard`:
   - `pub fn new() -> anyhow::Result<Self>`: calls `crossterm::terminal::enable_raw_mode()`, then constructs `CrosstermBackend::new(std::io::stdout())`, then `ratatui::Terminal::new(backend)`. Note: do NOT call `ratatui::init()` — that helper enters alternate screen. Construct manually.
   - `pub fn terminal(&mut self) -> &mut ratatui::Terminal<CrosstermBackend<std::io::Stdout>>`: returns mutable reference

4. `impl Drop for TerminalGuard`: calls `let _ = crossterm::terminal::disable_raw_mode();`. No alternate screen to leave.

Update `src/main.rs`:
- Call `terminal::install_panic_hook()` as the very first line of `main()`, before argument parsing
- After argument parsing and context detection, call `TerminalGuard::new()?` and hold the guard for the session duration (later plans will use it for rendering)
- For now, immediately drop the guard (session is zero-length stub) — this tests the cleanup path

Add a `#[cfg(test)]` integration note: write a test that calls `install_panic_hook()` and confirms it doesn't panic on installation.
