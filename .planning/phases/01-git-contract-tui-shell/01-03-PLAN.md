     - Status bar style: dark background (Color::DarkGray), white text

Update `src/main.rs` to wire the complete flow:

```
1. install_panic_hook()  ← must be first
2. parse argv[1] with Cli::parse()
3. verify path exists: if not, eprintln!("error: file not found: {path:?}") and process::exit(1)
4. read file to String: std::fs::read_to_string(&path)?
5. detect_context(&path)
6. App::new(content, context)
7. TerminalGuard::new()?  ← enters raw mode
8. Event loop:
   loop {
       terminal_guard.terminal().draw(|f| renderer::render(f, &app))?;
       match crossterm::event::read()? {
           Event::Key(KeyEvent { code: KeyCode::Char('s'), modifiers: KeyModifiers::CONTROL, .. }) => {
               match app.apply(Action::Save) {
                   Outcome::Save => {
                       drop(terminal_guard);  // restores raw mode BEFORE file write
                       writer::write_atomic(app.content(), &path)?;
                       process::exit(0);
                   }
                   _ => {}
               }
           }
           Event::Key(KeyEvent { code: KeyCode::Esc, .. }) => {
               match app.apply(Action::Cancel) {
                   Outcome::Cancel => {
                       drop(terminal_guard);  // restores raw mode
                       process::exit(1);
                   }
                   _ => {}
               }
           }
           _ => { app.apply(Action::Noop); }
       }
   }
```

Key ordering constraints:
- `drop(terminal_guard)` MUST happen before `process::exit()` — otherwise Drop never runs
- File write MUST happen after raw mode is restored — prevents garbled output on write errors
- `process::exit()` bypasses normal Rust unwinding; the drop(terminal_guard) call above is the mechanism that ensures cleanup
- On Windows, filter key events to `KeyEventKind::Press` only to avoid duplicate events

Import `crossterm::event::{Event, KeyCode, KeyEvent, KeyModifiers, KeyEventKind}` and `std::process`.
