Run the following verification steps in sequence:

1. **Build verification:** Run `cargo build --release` to confirm the project compiles in release mode without errors.

2. **Local install:** Run `cargo install --path .` from the project root. This installs the binary to `~/.cargo/bin/gitmedit`. Confirm exit code 0.

3. **PATH check:** Run `which gitmedit` (or `where gitmedit` on Windows) to confirm the binary is found in PATH. Expected output: a path containing `.cargo/bin/gitmedit`.

4. **Install list check:** Run `cargo install --list | grep gitmedit` to confirm gitmedit appears in the installed crates list.

5. **Version/help smoke test:** Run `gitmedit --help` or `gitmedit --version` to confirm the binary executes (it may not have --help/--version flags -- that is OK; a non-zero exit due to missing file argument is also acceptable as long as the binary runs).

6. **cargo publish --dry-run:** Run `cargo publish --dry-run` to confirm the package is ready for crates.io publication. This validates all metadata fields, README inclusion, and package structure without uploading.

7. **Package contents:** Run `cargo package --list` and confirm the output includes:
   - Cargo.toml (or Cargo.toml.orig)
   - README.md
   - LICENSE
   - src/main.rs
   - src/*.rs (all source files)

If any step fails, diagnose and fix the issue. Common problems:
- `cargo install --path .` fails with missing metadata: re-check Cargo.toml from Plan 01
- `which gitmedit` returns nothing: `~/.cargo/bin` is not in PATH -- document this finding but do not modify shell config (cargo itself prints a warning)
- `cargo publish --dry-run` fails: check for missing required fields

Note on INSTALL-01: REQUIREMENTS.md says `cargo install --path crates/gitmedit` but the project is a single-crate at root (no `crates/` directory exists). The correct command is `cargo install --path .` from the project root. This is consistent with the actual project structure and the STATE.md decision "[Phase 01-01]: Single-crate package not workspace."
